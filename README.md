# SQL Data Warehouse Project

A SQL Server data warehouse project built using a Medallion Architecture (Bronze, Silver, and Gold) to transform raw transaction data into an analytical model optimized for business intelligence and reporting.

The project demonstrates the complete ETL process, including data ingestion, cleaning, standardization, dimensional modeling, and fact table creation using T-SQL.

---

# Project Overview

This project simulates the implementation of a modern data warehouse for transaction data generated by food and beverage sales.

The solution follows a three-layer architecture:

- **Bronze** – Raw data ingestion
- **Silver** – Data cleansing and transformation
- **Gold** – Dimensional model for analytics

The final result is a star schema ready to be consumed by BI tools such as Power BI.

# Data Pipeline

## Bronze Layer

Responsible for ingesting raw CSV files without transformations.

Main responsibilities:

- Bulk loading CSV files
- Preserving original data
- Registering loaded files
- Preventing duplicate loads
- Loading event reference data

---

## Silver Layer

Responsible for cleaning and standardizing the data.

Transformations include:

- Data type conversion
- Commerce name standardization
- Product name standardization
- Device identifier parsing
- Missing value handling
- Date extraction from source files
- Data quality improvements

---

## Gold Layer

Implements a dimensional model using a star schema.

Dimensions:

- dim_evento
- dim_produtos
- dim_maquinas

Fact tables:

- fact_vendas
- fact_pagamentos

Business rules such as courtesy transactions and excluded commerce locations are applied during this stage.

# ETL Workflow

1. Load CSV files into the Bronze layer
2. Clean and standardize the data in Silver
3. Build dimensions and fact tables in Gold
4. Query the analytical model using SQL or BI tools

# Sample Business Rules

Some transformations implemented during the ETL process include:

- Standardization of commerce names
- Standardization of product names
- Parsing Clover device identifiers
- Extraction of event dates from source file names
- Removal of courtesy transactions from analytical tables
- Exclusion of non-analytical sales locations
